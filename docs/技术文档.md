# Desktop Pet 技术文档

## 1. 项目目标

一个有“专属感”的 Windows 桌面宠物：

- 用自己上传的照片生成宠物形象，可在历史宠物之间随时切换；
- 喂食、抚摸、聊天，宠物有饥饿度 / 心情 / 亲密度；
- 连续使用电脑过久时提醒休息，并定期主动问候心情；
- 全部数据保存在本地，离线可用；可自愿开启开机自启动。

## 2. 技术选型

| 需求 | 方案 | 原因 |
| --- | --- | --- |
| 桌面常驻窗口 | Python 3 + tkinter | Windows 自带 Tk，无需安装额外运行时，双击 bat 即可跑 |
| 透明无边框 | `overrideredirect` + `-transparentcolor` 颜色键 | tkinter 原生能力，不引入 Qt/Electron 的体积 |
| 图像处理 | Pillow | 缩放、羽化、圆角、合成都有高质量实现，且只依赖一个包 |
| 陪伴对话 | 本地话术库 + 可选 OpenAI 兼容接口 | 默认零配置可用；想更自然时填 Key 即可切换大模型 |
| 久坐检测 | `user32.GetLastInputInfo` + `kernel32.GetTickCount64` | 系统级键鼠空闲时间，不需要全局钩子、不采集内容 |
| 开机自启 | `HKCU\...\CurrentVersion\Run` | 只影响当前用户，免管理员权限 |

运行时依赖只有 `Pillow`，见 `requirements.txt`。

## 4. 关键实现

### 4.1 透明桌宠窗口

`PetWindow` 使用 `Toplevel` + `overrideredirect(True)` 去掉标题栏，设置 `-topmost` 置顶，并用
`wm_attributes("-transparentcolor", "#FF00FE")` 把画布底色当作透明色键。

tkinter 的颜色键是逐像素精确匹配的：半透明像素会先与画布底色混合，出现一圈品红色描边。
因此所有展示到桌宠窗口的帧都经过 `_solid_alpha()` 处理——alpha ≥ 100 置为完全不透明，否则完全透明。
代价是边缘没有 16 位平滑，但 900px 原图缩到 160px 后视觉上不可见（实测截图无描边）。

气泡同理，改用 Canvas 直接绘制白色圆角多边形与文字，使文字抗锯齿只与白底混合，不会碰到颜色键。

### 4.2 照片抠图

`imaging._cutout()` 的流程：

1. **取背景色**：沿四条边等距采样，逐通道取中位数，抗噪；
2. **扫描线漫水填充**：从四边所有像素出发，颜色距离在阈值内的区域标记为背景。
   只清理与边框连通的像素，因此主体内部的近似色不会被误删；
3. **腐蚀 1 像素**：`MinFilter(3)` 去掉原背景留下的描边；
4. **羽化**：对 alpha 通道做高斯模糊；
5. **裁切**：按 alpha > 12 的包围盒裁掉空白，四周留 6px。

阈值由界面上的“容差”映射：`(8 + 容差 × 2.2)²`，容差越大越容易判定为背景。
当抠图结果小于 16px（背景太杂导致主体被吃掉）时自动退回“原图卡片”模式：

- 阴影层（圆角矩形 + 高斯模糊）+ 白色圆角底板 + 圆角遮罩贴图，
- 适合背景复杂的照片，保证一定能生成可用形象。

性能：900×700 的图片在 Python 3.14 上约 0.38s，界面中的预览使用 560px 上限并做 200ms 防抖。

### 4.3 动画与立体感

- **呼吸**：从原图生成 12 帧，缩放系数 `1 + 0.024·sin(2πi/12)`，50ms/帧；
- **浮动**：水平正弦轻摆 1.4px、垂直 2.2px，和呼吸叠加；
- **地面投影**：椭圆羽化后按阈值硬边化（颜色键透明窗口不能有半透明像素，否则会与键色混出描边），
  预渲染 0.7/0.8/0.9/1.0/1.08 五个尺寸；跳跃升高时投影同步缩小，位置始终贴地；
- **镜像**：向左走动时切换到水平翻转帧；
- **走动**：状态机 `idle → walk → idle`，每次随机 45–150px，每 50ms 水平移动 3px；
  走动时叠加 5px 小跳与 ±5° 倾斜帧，碰到屏幕边缘自动掉头，走完保存坐标；
- **小动作**：`jump / look / shake / stretch / sit` 五种，每 15–32s 随机触发；
  蹦跳时整体上移 30px 并缩小投影，张望时切换侧身帧，坐下时压扁 1.10×宽、0.88×高；
- **挤压**：喂食、抚摸、拖拽落地时显示压扁帧 0.35–0.9s，模拟“Q 弹”反馈。

帧在启动时一次性预渲染为 `PhotoImage`（含镜像帧和动作帧），统一按底边居中对齐，
保证呼吸、走动、跳跃时“脚”始终踩在同一条线上；每帧只做 `itemconfigure` + `coords`，不重复解码图片。


### 4.4 养成数值

`state.json` 中每只宠物独立保存 `hunger / mood / affection / feeds / pets / history`。

- 饥饿度每分钟衰减 0.2（约 8 小时饿扁），心情每分钟衰减 0.06；
- 衰减按 `last_seen` 计算，因此关机、休眠期间同样生效，但有下限（饥饿 8、心情 10）；
- 喂食：+14～26 饱腹、+4～8 心情、+1 亲密；抚摸：+2 心情、+1 亲密。

### 4.5 久坐提醒

`reminder.ActivityTracker` 每 5 秒被主循环调用一次：

1. `GetLastInputInfo` 得到距最后一次键鼠输入的秒数；
2. 空闲超过 `idle_reset_min`（默认 5 分钟）视为离开，连续使用时长清零；
3. 否则累加活跃时长，达到 `rest_interval_min`（默认 50 分钟）触发提醒；
4. 触发后记录 `_rest_ready_at = now + rest_snooze_min`，即使用户继续忙，最早也要 15 分钟后再次提醒；
5. 心情问候使用独立的 `mood_check_min`（默认 120 分钟）计时。

提醒以气泡形式出现，点击气泡直接打开聊天并带入一句关心的开场。

### 4.6 对话路由

`dialogue.reply(history, pet, user, llm)`：

- 若配置了 `enabled + base_url + api_key + model`，调用 OpenAI 兼容接口
  `POST {base_url}/chat/completions`（若填的是完整地址则不再拼接）；
- 系统提示词限定角色、长度（≤80 字）、先共情再提问、不做专业诊断、危险表达时引导求助；
- 请求在后台线程执行，结果经 `queue.Queue` 回到 UI 线程，避免界面卡死；
- 任何异常（网络、鉴权、格式）都会自动回退到本地话术，并在聊天窗口用灰色小字说明原因。

本地话术按关键词（累 / 焦虑 / 难过 / 孤独 / 开心 / 生气 / 睡眠 / 饥饿 / 礼貌用语）命中，
每个意图有多条候选，随机选择，避免重复感。

### 4.7 启动与稳定性

- `main.py` 先调用 `SetProcessDpiAwareness(2)`，避免 125%/150% 缩放下模糊；
- 用命名互斥体 `DesktopPet_SingleInstance` 防止重复启动；
- 启动异常写入 `data/app.log` 并弹窗提示；
- 配置写入使用“临时文件 + `os.replace`”，断电也不会留下损坏的 JSON。

## 5. 数据格式

`pets.json`：

```json
[
  {
    "id": "71d5259690eb",
    "name": "团子",
    "mode": "cutout",
    "source": "IMG_1234.jpg",
    "created_at": 1792842000.5,
    "image": "data/pets/71d5259690eb/pet.png",
    "thumb": "data/pets/71d5259690eb/thumb.png"
  }
]
```

`state.json`：

```json
{
  "active_pet_id": "71d5259690eb",
  "stats": {
    "71d5259690eb": {
      "hunger": 86.4,
      "mood": 74.2,
      "affection": 12,
      "feeds": 3,
      "pets": 8,
      "last_seen": 1792845600.0,
      "history": [{"role": "me", "text": "今天有点累", "ts": 1792845000.0}]
    }
  }
}
```

`config.json` 保存所有设置；`llm.api_key` 为明文，仅存储在本机，不会上传到除你配置的接口以外的任何地方。

## 6. 部署与迁移

- 首次：双击 `setup.bat` 安装 Pillow（或 `python -m pip install -r requirements.txt`）；
- 日常：双击 `run.bat`；
- 自启动：设置窗口中勾选，写入当前用户注册表，命令行指向 `pythonw.exe main.py`；
- 迁移：直接复制整个文件夹（含 `data`）到新电脑，重新运行 `setup.bat` 即可；
- 卸载：设置中关闭自启动，删除整个文件夹。

## 7. 已知限制

1. 仅支持 Windows（注册表自启、`GetLastInputInfo`、颜色键透明都是 Windows 行为）。
2. 颜色键透明不支持逐像素半透明，边缘使用阈值 alpha；若需要真正的 32 位分层窗口，需改用
   `UpdateLayeredWindow`（代码量会明显增加）。
3. 抠图面向“主体清晰、背景较干净”的照片，复杂背景请用原图卡片模式。
4. 大模型回复质量取决于所配置的服务商与模型。

## 8. 参考的开源项目

本项目没有直接复制代码，设计与交互借鉴了以下成熟桌宠项目的通用做法：

- **VPet**（<https://github.com/LorisYounger/VPet>）：C#/WPF 桌宠，验证了“状态数值 + 互动 + 多形象”
  的产品结构，本项目的饥饿度/心情/亲密度和喂食菜单参考其思路；
- **Shimeji-ee**（Java 桌宠，Shimeji 的增强版）：无边框置顶窗口、拖拽、右键菜单、随机走动，
  是本项目窗口行为的经典范式；
- **oneko.js**（<https://github.com/adryd325/oneko.js>）：网页版猫猫跟随鼠标的实现，
  说明“低成本动画 + 位置更新”就足以让桌宠显得有生命感，本项目的呼吸/摆动帧即采用该思路。

## 9. 可扩展方向

- 宠物叫声（`winsound` / 音频文件）；
- 更多动作帧（挥手、睡觉、被拖动时挣扎）；
- 番茄钟与屏幕使用统计；
- 将抠图换成 `rembg`（U2Net）以支持复杂背景，代价是模型体积与推理时间上升。
